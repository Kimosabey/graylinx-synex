# 4. User Flow — What Happens When Someone Uses AI

| **Step** | **What happens in simple English** | **Example** |
|---|---|---|
| 1. User asks | User types or speaks a question/request. | “Why is Chiller-03 unhealthy?” |
| 2. Identify user | Graylinx knows who is asking and their role. | Reliability Engineer |
| 3. Check access | System checks which customer/site/equipment/data the person can see. | Only Plant A assets |
| 4. Understand request | AI decides whether this is a question, report, investigation or action. | Investigation |
| 5. Get information | AI gets the needed equipment data, ML/FDD results, WOs or documents. | FDD + history + SOP |
| 6. Check quality | System checks whether the information is current and good enough. | Valid operating state |
| 7. Answer/explain | AI gives a simple answer and shows supporting proof. | Likely condenser issue |
| 8. Suggest next step | AI offers useful actions. | Inspect condenser / create WO |
| 9. Control action | Before changing anything, rules, risk and approval are checked. | WO approval required |
| 10. Execute | Approved system/tool performs the action. | WO created |
| 11. Verify | Graylinx checks the result after the work. | Fault cleared |
| 12. Record | The action, result and proof are recorded for reports and audit. | Verified repair |
