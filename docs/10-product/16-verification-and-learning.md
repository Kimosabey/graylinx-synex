# 16. Verification and Learning

| **Verification** | **Evidence** | **Outcome** |
|---|---|---|
| Telemetry verification | Post-work readings/residuals | PASS / FAIL / UNKNOWN |
| Technician verification | Checklist/findings | PASS / FAIL |
| **Supervisor acceptance** | Review of critical work | ACCEPT / REWORK |
| FDD verification | Fault clears under valid operating conditions | CLEAR / PERSIST |
| Business verification | Downtime/energy/reliability outcome | Outcome measured |

## 16.1 Learning workflow

OUTCOME → CAPTURE HUMAN OVERRIDE/RESULT → CLASSIFY SUCCESS/FAILURE → UPDATE CASE LIBRARY → EVALUATE FDD/AGENT/POLICY → CONTROLLED CHANGE → validation → APPROVAL → RELEASE.

- Do not automatically retrain from a single user correction.
- Human feedback becomes a governed signal.
- Production changes require evaluation and rollback feature.
